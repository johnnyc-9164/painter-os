# Public marketing and admin application boundary

`apps/marketing` is a separate Next application with its own build/layout/routes. `apps/web` remains the admin application and preserves all existing routes, including `/site`, `/p`, `/i` and `/api/auth`. This is an additive source separation, not a completed deployment or domain cutover.

Admin authenticated commands remain the sole CMS write authority: article.create/update/publish in the existing domain engine and Painter backend. Marketing calls only the existing anonymous `painter:articles` query, which projects published AND public content for the selected workspace. The shared published-article contract validates and strips fields, renders content as escaped text, and exposes no drafts. No second store, session provider, migration or public preview endpoint is introduced. Existing public queries collect all matching records; this change does not claim bounded pagination.

Build independently with `npm run build:marketing`; admin continues `npm run build`. Standard monorepo `check-types`, `lint` and `test` include both owned apps and public contract tests. Acceptance still requires actual builds of both applications. Changing the root build command remains held until the existing Vercel repository root/build command/output selection is verified; merely building both `.next` directories does not select the correct deployment artifact. The prepared workflow addition is preserved, but the implementation credential cannot update workflow files. Marketing uses only existing Next/React/Convex dependency versions. Workspace lock metadata was updated offline without installing modules. Local full builds are blocked by missing dependencies and limited task disk; CI is required evidence before acceptance.

For a future separate marketing deployment, select repository root `apps/marketing` and its local `npm run build` (or monorepo root with explicit `npm run build:marketing` and marketing output ownership). Do not copy the admin production Convex deployment command into marketing. Supply only public `NEXT_PUBLIC_CONVEX_URL` for the same existing backend and optional validated `NEXT_PUBLIC_ADMIN_ORIGIN`; absent admin origin omits the CTA. No deploy key, Better Auth secret or link-signing secret belongs in the marketing environment.

Cutover gates: choose canonical marketing/admin origins, route old workspace URLs and `/p`/`/i` to admin, verify auth callbacks/cookies and the single backend SITE_URL/trustedOrigins plus admin PAINTER_APP_URL, and test CMS publish -> anonymous article read on the same backend. Do not assume shared cookies across hosts or add arbitrary trusted origins. Keep existing admin public-site compatibility until old links are proven. Rollback before cutover is removal of the unused marketing deployment; rollback after cutover restores the reviewed routing configuration while retaining admin routes and CMS data. This PR performs no provider configuration, deploy, secret read or destructive deletion.

The existing admin route's Next agent guide points at installed documentation, which is unavailable in this disk-limited checkout. Official Next layout/page guidance was read as fallback: https://nextjs.org/docs/app/getting-started/layouts-and-pages . No existing web route was edited.
