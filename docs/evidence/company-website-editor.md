# Company website editor preparation

Issue [#125](https://github.com/johnnyc-9164/painter-os/issues/125) adds `/content/website` inside the existing authenticated company admin. Existing Content Studio article authoring, journal, portal, invitation and business URLs are preserved. The editor reuses the shadcn primitives in `packages/ui`, the sole domain website contract/validators, and the exact shared `CompanyWebsite` renderer/catalog used by the public company site. It does not import another app or create another CMS/store.

Owners and office administrators can author company identity, logo/main photo, services, project photos/gallery, genuine company-authored testimonials, pricing, phone/email/address/service areas/hours, blog visibility and Studio/Editorial/Direct templates. Blog writing remains in Content Studio; preview reads only a bounded published-article summary page. Photos come exclusively from the dedicated verified website-media library, never private job files or arbitrary URLs. Save the draft to resolve a newly selected photo in the private preview. Unsaved preview is labelled; publishing is disabled until the draft matches the last confirmed saved state. Publish/unpublish are explicit revision-safe actions; unpublishing retains the saved draft and any local text edits.

`/api/website` and `/api/website/media` use the existing lazy Better Auth bridge. Each operation validates the actual current session; backend functions independently resolve current enabled membership and owner/office permissions. JSON/status/upload requests require a bounded expected-actor header compared against the authenticated user ID. This detects stale browser account context and grants no identity or role authority. Native image requests use the canonical private proxy URL and current authenticated backend membership. Confirmed 401/403 erase private editor/media/upload/intent state, including initial-load errors; focus revalidation and a generation guard prevent late replies from restoring discarded private state. Account/workspace/role/runtime changes remount the editor.

Writes retain the existing intent journal's key after an unknown result. Requests allow only their explicit operation fields, use an actual streamed 256 KiB JSON limit, and cap multipart at 3 MiB plus 64 KiB overhead with a 3 MiB file limit. The server submits image bytes to the dedicated authenticated backend action; it never adopts browser storage IDs. Unknown uploads retain their selected file and nonce, require a status check, and permit same-key retry only after a confirmed null receipt. Each further unknown outcome requires a fresh status check. Admitted/unknown/deleted operation rows remain backend-owned; no second storage writer is authorized by UI state. Private replies/images use no-store, nosniff and image same-origin resource policy. Local demo save/upload/publication are explicitly unavailable.

Verification uses synthetic local fixtures. Focused tests exercise actual Next request handlers/server adapters with an intercepted authenticated bridge, strict fields/body/query limits, role/revision errors, stale A/B account comparison, byte-only media transport and private image headers. Browser tests run the production-built Next editor on an owned secret-free loopback server with `/usr/bin/chromium` sandbox enabled and intercepted synthetic authenticated APIs. They verify conflicts retaining edits, saved-only publication, account/tenant reset, initial 401/403 recovery, cookie-switch private reset, late-response suppression, repeated unknown upload status/retry behavior, real form controls, shared template preview and mobile overflow. They **do not prove deployed Better Auth cookies/JWTs, live storage, provider activation or company ownership**.

The initial browser strict-locator failure is preserved under private `.agent/runs/website-editor-initial-browser-failure-e8e18a78-d0b7-43ab-8f81-0782085df95c`; it collided with Next's route announcer. The first batched visual pass found editor paragraph colors leaking into the shared preview and a capture taken during sidebar transition; scoped selectors and capture settling repaired these. A distinct preliminary reviewer found initial auth denial could leave loading active; the repair and explicit regression are included. Subsequent account-context hardening follows that source review. Exact final receipts, CI and independent review belong to the PR rather than invented deployment claims.

Reused [Painter PR evidence](../skills/painter-pr-evidence/SKILL.md), the installed Next.js route-handler/client-boundary guides and Impeccable's existing-surface/craft guidance. The established Artisan admin identity is extended; public template world/token ownership remains with the shared renderer implementation. No new reusable skill is needed: this task adds product-specific authoring and reuses the existing evidence procedure.

Rollback removes the editor nav/mount and owned API/client modules together. Backend/public projection and shared template source are separately owned dependencies; no automatic data deletion or private-file migration accompanies rollback. No deployment environment values, provider/account resources, cookie-domain cutover, automatic contact collection or production activation were performed. Broad four-app live readiness remains open.
