# Host-owned AgentMail cache boundary

Refs #21. Binding is a trusted host assignment, not provider mailbox ownership verification. The existing `painter.ts` membership resolver is exported unchanged and reused; Better Auth remains identity authority. `painterEmailBindings` adds one disabled binding per tenant, with indexed checks preventing the same inbox being bound to another tenant. Only an internal owner-authorized mutation can assign it; office admins can read but cannot assign. Existing assignments replay unchanged or reject conflicting replacement. No activation argument exists.

The authenticated public query takes an explicit workspace selector, resolves real enabled membership and owner/office-admin permission, then derives the inbox ID exclusively from the server binding. It calls actual official `AgentMail.getCachedInbox` for one indexed cache row. A typed projection exposes only configured sender (bounded to 254 characters), binding/cache presence and literal disabled/unverified state. Provider cache email, IDs, pod/client metadata, display name, raw mail and bodies never leave this boundary. Cache presence is not freshness, connection, sender verification or activation evidence.

The [pinned official client](https://github.com/agentmail-to/convex/blob/46bde1a9132599760f425b55c9e29d5ba86ea7df/src/client/index.ts) constructor receives `webhookSecret: ''`, preventing its environment fallback; cached queries perform no provider API call. The [official component](https://github.com/agentmail-to/convex/blob/46bde1a9132599760f425b55c9e29d5ba86ea7df/src/component/lib.ts) cache is global, so no component list is exposed. Its outbound status API lacks inbox ownership in the returned DTO; accepting arbitrary outbound IDs would be unsafe. Outbound status awaits a separately reviewed trusted receipt mapping.

Actual component tests use exported `@agentmail/convex/test`, its real schema/functions and real SDK. Only auth identity lookup is mocked; actual host resolver, database and authorization execute. Test-only fixture cache rows do not create remote mailboxes. Tests cover owner/internal registration, replay/conflict, global inbox uniqueness, tenant/role/revocation denial, actual cache hit/miss, bounded projection stripping oversized/private provider metadata, extra identifiers/activation rejection, and zero provider environment lookup/fetch. `convex-test` is a mock backend, not deployed-provider acceptance.

Outbound, inbound and auth email activation remain held. This change has no send receipt, enqueue/send/retry, mailbox CRUD, provider remote read, webhook verification/parser/route, credential access, sender proof or auth callback installation. No manifests/lockfiles change. Secure credentials, explicit approved sender/inbox ownership and approved live acceptance remain prerequisites for a future enablement decision. Ambiguous provider retry policy remains a separate review.

Validation: native combined regression and diff checks can run locally without dependencies; actual SDK/component tests and locked types/build execute in fresh CI. Exact head, commands/results and independent review are recorded on the PR.
