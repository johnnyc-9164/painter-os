## Typed source projection

New pure contracts project only an approved source URL, trusted fetch time, bounded text/quotes, SHA-256 of the retained excerpt and explicit source/truncation/unstored/completeness flags. Provider raw JSON, screenshots, credentials and diagnostic messages never enter the projection. Evidence remains `unverified`, and content—including embedded instructions—never grants business write authority or creates a bid/price/deadline fact.

Limits: five projected pages, 16 KiB retained UTF-8 content per page, eight 240-byte quotes per page, and a proposed 15-second source fetch timeout. Projection limits are not a claim that upstream response bytes or paid credits are already capped. Source hashes explicitly describe only retained excerpts, not a full dropped document.

The URL policy allows exact approved HTTPS origins and query keys, rejects credentials, fragments, unusual ports, literal IP/private/local names and unapproved reported redirect destinations. It does not verify DNS rebinding, a hidden redirect chain or network resolution at the remote scraper. That limitation is explicit in every projection; production remains disabled until the network/provider policy is reviewed. Metadata URLs and source text are untrusted.

Completed provider state is not verified evidence. Missing/invalid counters, unstored pages, rejected sources, page/content truncation or missing content keep the crawl partial. Provider 402/429 become safe refusal codes; an ambiguous start remains `start_unknown`, without claiming cancellation undid remote paid work.

## Persisted host ownership and current authority

One additive `painterBidSourceOwnership` table stores the trusted tenant/creator, replay-bound operation/source URL, component crawl ID, terminal callback digest and deletion tombstone. Indexed unique lookups enforce operation replay and component mapping; concurrent binding admits exactly one mapping. It does not store crawl progress/pages or introduce a host/Pi retry queue. Trusted private preparation accepts a host-owned URL policy, never a browser permission grant. Positive preparation, binding and SDK controls are registered only in local fixture modules. Production exports an authenticated disabled availability mutation and an internal completion callback, with no provider client, mount, activation toggle or public write/start/control endpoint.

Fixture read/page/list/cancel/delete/resume controls authorize current Better Auth identity and existing Painter membership/capability before the actual SDK operation. Lists query at most 26 ownership rows and reject overflow rather than materialize a global component list. This is a bounded 25-record window, including tombstones; sustained history requires future indexed pagination, and this slice does not claim an unlimited/scalable listing. The actual client does not see host authentication. Action authorization and an external provider request are separate steps, so this is not an atomic revocation guard across a network call. Provider-budget admission remains unavailable and production is disabled.

The internal callback accepts closed bounded arguments and computes a SHA-256 receipt from crawl ID/terminal status/page/unstored counters, excluding raw diagnostics and ignored context. It resolves ownership only by its unique persisted crawl ID, then rechecks the stored creator's actual Better Auth identity, enabled membership, current bid capability and workspace existence. Callback context supplies no tenant/actor/role authority. Identical completion replay is inert; altered replay, unbound/deleted mapping, disabled membership, changed role, deleted user or workspace all fail closed. Callback pages/content remain unverified and create no business records. A callback arriving before binding fails closed; ambiguous external starts and early/lost callback reconciliation remain live-activation holds rather than a new durable host queue.

Actual component cancellation invokes the host completion callback through its scheduled function handle. Local deletion removes component-owned records and preserves a host tombstone; it makes no claim to undo paid requests or remote provider work. The fixtures cover actual SDK controls, callback scheduling/replay, cross-tenant and customer refusal, current revocation/deleted identity/workspace, URL/operation replay, concurrent component uniqueness and bounded-list overflow.
