## Authority and bounded contract

This is an internal-only capacity foundation. `intakeAdmission.admit` resolves the actual workspace and its indexed enabled intake configuration on every invocation, before receipt replay or quota access. Missing/deleted workspace, missing/disabled policy, malformed enabled policy and ambiguous policy fail closed. No browser actor/IP dimension, public endpoint, lead writer, customer PII, provider request, paid-model allowance, financial ledger or new identity authority is introduced. Digest format is verified; a future trusted dispatcher must derive the digest from actual bounded input and resolve the public site's workspace. A submitted digest cannot establish authority.

Request keys are 8–80 opaque ASCII identifier characters; payload digests are 64 lowercase hexadecimal characters. Receipt fields contain only that metadata, workspace/policy revision, small result and numeric timestamps. No underlying intake payload is stored. Current policy is checked before any replay; revision changes require fresh admission with a new key. Same-key/different-digest conflicts deny without another debit.

## Actual component semantics

Pinned installed `@convex-dev/rate-limiter` 0.4.1 is an additive mount; Better Auth, Contractor OS, painting and AgentMail remain. Hand-authored runtime bindings add its actual installed `ComponentApi` type. Existing auth-email budget and AI money/reservation stores remain separate.

Two unsharded synchronous transactional fixed windows start at Unix epoch: 30 deployment-wide attempts/minute and 5 attempts/minute per enabled tenant. Both dimensions are called in one parent mutation. They count unique valid enabled-policy attempts while capacity remains, including an attempt rejected by the other dimension. Upstream saturated dimensions return denial without decrementing further. This is deliberately attempted-request accounting, **not** atomic admitted-only fairness. A returned structured quota denial commits any successful dimension debit plus its receipt when at least one dimension debits; a thrown parent error rolls back nested component debits and host receipt. No reservation debt, asynchronous updates or extra host queue is used. The package's required `batch-worker` 0.3.5 child is upstream implementation support; this synchronous path never enqueues it or replaces Pi lifecycle.

Rate admission is not comprehensive bot protection. Malicious traffic may still exhaust a shared global quota, contend on the global row, or create denial receipt/maintenance load; no global denial-of-service or dollar-spend protection is claimed.

## Receipt horizon and maintenance

Receipts deduplicate admission for ten minutes. Recorded admitted and partial-debit quota-denied outcomes replay without a second debit while policy is unchanged; denied replay adjusts the remaining retry interval but stays denied. Retrying a recorded denied logical attempt requires a new key. Expired receipts explicitly deny until removed; there is no silent expired allow. `cleanupExpired` is an internal indexed, bounded maintenance mutation that deletes at most 100 expired records, reporting more work. Fresh receipts are preserved. After expiry and explicit cleanup, the same key is a new capacity attempt. This finite horizon is **not** eternal business/effect idempotency; the future lead/effect writer must own that separately. Cleanup is prepared, not scheduled or remotely run in this slice. When both dimensions are saturated, neither debit nor new receipt occurs: unique rejected keys cannot add receipt writes. These unrecorded denials may be freshly admitted next window. Partial-debit denials retain receipts. TTL bounds dedup duration; maintenance and continuing windows still require operational capacity.
