# Office estimate appointment UI preparation

Issue [#147](https://github.com/johnnyc-9164/painter-os/issues/147), a child of #78 consuming the sole writer from #141. `/schedule/estimates` preserves the existing project scheduling route and adds offered estimator slots, qualified inquiry proposals, explicit internal approval/cancellation and revision-safe rescheduling. Owners and office administrators can write; estimators see only their own assigned slots/visits and receive no CRM source names, contact fields or resource roster. Other roles and local demo reservations are unavailable.

The existing Better Auth bridge resolves the actual current user and workspace membership before choosing office or estimator projections. Every backend function independently rechecks authority. The expected-actor header detects a stale browser account; it grants no authority. Backend sources establish current qualified/customer-linked eligibility; office-only authorized CRM snapshot data supplies bounded display names. Names and contacts are never copied into appointment records. These multi-query reads are not a single atomic snapshot, and accepted in-flight data cannot be recalled after revocation. Focus revalidation, account/role/workspace remounts and generation guards clear private state on confirmed denial or downgrade; late replies cannot restore discarded state. Independent review found that a role downgrade needed to invalidate the generation before applying its new projection; the common application seam now does that for focus, reload, initial load, write refresh and pagination. A delayed office response released after an estimator downgrade verifies the repair.

Shared shadcn Button/Input/Label controls extend the established white/blue admin. Local date/time requires an explicit IANA zone and numeric offset, with domain validation before submission and authoritative server normalization. Buffer minutes are visible. Approval, cancellation and slot closure use an explicit inline confirmation; closure preserves existing reservations. Time labels use the stored zone, not browser-local time. Product copy consistently says proposal/internal reservation, with `nativeOnly:true`, `customerNotified:false`, `externalCalendarsChecked:false` checked by the transport decoder. No public booking, customer notification, calendar/provider connection or autonomous write is enabled.

Unknown results retain the exact command and request key in component memory and disable additional changes until same-action reconciliation. Reloading keeps that reference. The transport allows current-record correction for narrow resource-unavailable, expired-slot, qualified-source/transfer and invalid-transition refusal codes in synthetic fixtures. Production recovery remains held until the backend emits a closed structured `ConvexError.data` contract and the gateway consumes it; ordinary error-message fixtures do not prove production-safe code delivery. Unknown or stripped production failures keep the exact pending request. For recognized refusals, unknown or unrecognized errors retain their exact pending request. A confirmed revision/conflict or capacity refusal allows review/correction; it is not treated as success. Native capacity exhaustion is surfaced without claiming a reset or unsupported cleanup. Source pages replace the bounded selection page; slot/visit pages deduplicate by ID. No pagination field is permission authority. POST uses a real streamed 16 KiB bound and strict action fields; private replies remain no-store/nosniff.

Local verification uses intercepted synthetic bridge/API fixtures, never deployed auth or a live reservation. Focused tests execute actual Next handlers and server adapters plus strict decoder/transport, denied/local/loading shared rendering and time labels. Browser fixtures execute the production-built mounted UI in sandboxed Chromium, covering lost-result same-key replay, explicit approval, rescheduling, cancellation, slot/time-zone validation, mobile fit, estimator read-only projection and focus-denial clearing. Historical captures are labeled by their receipt, not relabeled as final-head or genuine cloud acceptance. The first default browser launch lacked its bundled binary; the installed `/usr/bin/chromium` ran with sandbox enabled. The first desktop capture retained fixed-sidebar scroll position; the next batched capture resets document position before desktop/mobile capture. Exact committed source/head/check receipts accompany the PR.

Applied installed Next16.3.8 route/client guides and Impeccable established-surface/craft guidance; the launcher was unavailable, so existing design context was read directly. Existing domain/Better Auth/Pi authorities take precedence over generic skill defaults. Reused [Painter PR evidence](../skills/painter-pr-evidence/SKILL.md); no new reusable operating procedure was warranted. Rollback removes the UI mount/nav and owned gateway/transport/component together; it does not erase backend records or reverse accepted internal reservations. Provider activation, production rollout, native-capacity lifecycle and genuine cloud acceptance remain separate holds.
