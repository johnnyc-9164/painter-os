## What primary sources actually establish

- Cloudflare PiHarness stores Pi tables in Durable Object SQLite and uses lifecycle heartbeat/alarm recovery. Both optional Pi peer packages must be >=1.0. The documented example uses TypeScript/JavaScript, not Python. https://developers.cloudflare.com/agents/harnesses/pi/
- Earendil calls Pi Durable experimental. Each task checkpoints; interrupted model requests rerun with partial answer marked aborted. Tool intent is persisted before execution; only replay-safe tools rerun automatically. Submission requestId dedup is not exactly-once external-effect execution. Storage has one process owner. Subagents are built as durable conversations/tools, not an automatic built-in orchestrator. https://earendil.com/posts/pi-durable/
- Cloudflare documents no built-in tool approval/permission step, event streams begin from snapshots (no replay cursor), no session deletion, and abort waits for idle/does not force a noncooperative tool to stop. The model may reason after unsafe interruption: the trusted dispatcher MUST block uncertain re-sends even if the model asks again. A custom beforeTool hook exists in Earendil examples, but memoized boolean approval alone is insufficient for tenant/arguments/version/revocation safety.
- Workflow records ordered steps/arguments/results, supports awaitEvent and restart, and uses Workpool internally. Actions may be retried; external outcomes still need idempotency/reconciliation. Cancellation does not stop already running actions. Workflow definition changes can cause determinism violations for existing runs. https://www.convex.dev/components/workflow
- Calling an entire ordinary Pi model/tool loop as one Workflow action checkpoints only the action boundary. Interruption may rerun that whole loop; safe granular recovery requires separately persisted prompts/tool intents and separately orchestrated idempotent steps. Convex Agent has documented workflow integration with saved promptMessageId, persisted threads, and reuse of existing responses. https://docs.convex.dev/agents/workflows
- Convex scheduled/workflow execution has null auth user. Stored actor IDs are not sufficient authorization: internal dispatch must resolve current enabled membership/role and bind workspace from trusted creation and grant boundaries. https://docs.convex.dev/agents/tools
- Convex Agent owns thread/message persistence and optional streaming/context/usage hooks. Installing it alongside Pi as a second transcript/agent-loop authority would create overlap. https://docs.convex.dev/agents/overview
- Workpool organizes bounded concurrency, retry/backoff, callbacks; use only for a separately owned Convex workload if needed, not a second queue controlling Pi tasks. In-flight cancellation has the same practical caveat. https://www.convex.dev/components/workpool
- Rate Limiter provides transactional keyed token buckets/fixed windows; it can enforce trusted workspace/actor limits, but tracking usage after a call is not a prepaid spend cap. Reserve budgets before calls and reconcile actual usage. https://www.convex.dev/components/rate-limiter ; https://docs.convex.dev/agents/usage-tracking
- Action Cache is @convex-dev/action-cache, version 0.3.1 in directory metadata, keys action name+args and TTL. Only cache read-only derivations with workspace, authorization scope, connection revision, content revision included. Never treat cache as delivery idempotency or approval. https://www.convex.dev/components/action-cache/llms.txt
- Zapier MCP is the callable integration transport for agents, with OAuth/account credentials/rate limits handled by Zapier. Zapier Platform CLI/SDK builds an integration publishing Painter OS triggers/actions to Zapier; it is a different product requirement, not the required client SDK for invoking existing apps. https://docs.zapier.com/mcp/home ; https://docs.zapier.com/integrations
- Zapier MCP home currently says each successful call consumes two Zapier tasks (failed calls do not). Exact connection arrangements, team sharing eligibility, and plan pricing must be checked at activation; deeper connection/usage pages did not yield usable fetch content, so do not assert unverified restrictions as facts.
- Durable Object costs include active wall-clock duration, requests/alarms, and SQLite reads/writes/storage; free tier limits cause failures. Heartbeat recovery/model restarts can add repeated provider charges. https://developers.cloudflare.com/durable-objects/platform/pricing/
